Initial Reconnaissance

As an assumed breach machine, we are provided with initial credentials, but it's always good practice to start with a standard Nmap scan to understand the network landscape and potential services available. This helps confirm the attack surface and identify any unexpected open ports.

Why

Even with initial credentials, a thorough Nmap scan is crucial for understanding the target's network footprint. It helps identify open ports, running services, their versions, and potential entry points or additional services that might not be immediately obvious or documented.

Command 
nmap -sC -sV -vv -oA outbound 10.10.11.77

nmap: The network scanner utility.
-sC: Performs a script scan using the default set of scripts. These scripts are generally safe and effective for discovery.
-sV: Attempts to determine service versions running on open ports.
-vv: Sets the verbosity level to 2, providing more detailed output during the scan.
-oA outbound: Outputs the scan results in all available formats (Nmap, Grepable, XML) with the base name "outbound".
10.10.11.77: The IP address of the target machine.

Initial Access: RoundCube RCE

As an assumed breach machine, we are provided with credentials: tyler:[PASSWORD_HERE]. Navigating to http://mail.outbound.htb reveals a RoundCube webmail login page. We'll attempt to log in with the provided credentials.

Why

With assumed breach scenarios, the first step is always to utilize the provided credentials on the expected service. In this case, it's RoundCube webmail, identified during reconnaissance.

Upon logging in, we identify the RoundCube version:

  • Version: 1.6.10

A quick search on CVE Details for "RoundCube 1.6.10" or "RoundCube RCE" reveals a relevant vulnerability:

  • CVE-2023-5631: RoundCube before 1.5.10 and before 1.6.11 allows RCE by authenticated users because a parameter is not validated. This is a deserialization vulnerability.
Concept: Deserialization Vulnerability

A deserialization vulnerability occurs when an application deserializes untrusted data without proper validation. Deserialization is the process of converting a stream of bytes back into a usable object. If an attacker can control the serialized data, they can inject malicious objects or manipulate existing ones to execute arbitrary code, bypass authentication, or cause denial of service. These vulnerabilities often arise when applications use PHP's unserialize() function or similar functions in other languages on user-supplied input.

The CVE description mentions public exploits are available, specifically highlighting a deserialization issue in PHP. We need to find a PHP-based exploit to ensure compatibility and avoid potential issues with language version differences or object structure mismatches if using an exploit written in a different language like Python.

Why

Using an exploit written in the same language as the vulnerable application (PHP for RoundCube) is critical for deserialization vulnerabilities. Different languages serialize objects differently, and even minor version changes within the same language can lead to incompatible serialized payloads, causing the exploit to fail. Mimicking the environment as closely as possible maximizes the chances of success.

Exploit Payload Analysis (Optional Deep Dive)

This is an example of the URL-encoded and obfuscated reverse shell payload embedded within the exploit.

Analyzing exploit payloads provides insight into how vulnerabilities are exploited, how to detect them (e.g., specific boundaries or obfuscation patterns), and how to potentially adapt them for different scenarios. Why

Web applications often store sensitive information like database credentials in configuration files. Gaining access to the database can lead to user enumeration, password hashes, and sometimes direct plaintext passwords, which can facilitate horizontal or vertical privilege escalation.

Concept: Triple DES (3DES) Encryption

Triple DES (3DES) is a symmetric-key block cipher, an enhancement of the original DES algorithm. It applies the DES algorithm three times to each data block with two or three distinct keys. 3DES was developed to compensate for the diminishing key size of DES against brute-force attacks. While stronger than single DES, it's considered less secure and significantly slower than AES (Advanced Encryption Standard), which has largely replaced it in modern applications. RoundCube uses it with the des_key for session data encryption.

Alternatively, we can manually decrypt the password using CyberChef. The encrypted string is Triple DES (3DES) encrypted in CBC mode. The decryption key is cK38xQ9k8k0m7w5s7xW8Wp7P from config.inc.php. The Initialization Vector (IV) is the first 8 bytes of the Base64-decoded ciphertext.

Command (to get IV)

echo "...": Prints the hexadecimal string of the encrypted password.
xxd -r -p: Converts the plain hexadecimal string back into its raw binary form.
head -c 8: Takes the first 8 bytes (64 bits) of the binary data, which will be our IV.
xxd -p: Converts the raw binary IV back into a hexadecimal string for display.

What This Tells Us

Privilege Escalation: Root (Below CVE)

With an SSH shell as jacob, the immediate next step for privilege escalation is to check sudo permissions.

Why

Checking sudo -l is a fundamental and often very quick step in Linux privilege escalation. It reveals which commands a user can run with superuser privileges, without needing to provide a password. Misconfigurations or vulnerabilities in these allowed commands can directly lead to root access.

Command 
sudo -l

This vulnerability allows an attacker to manipulate file permissions through a symlink race condition. When below is executed, it creates a directory /var/log/below and sets its permissions to 777. Inside this directory, it creates error_user.log and sets its permissions to 666. This behavior, if exploited with a symlink, allows us to change the permissions of an arbitrary file.

Concept: Symlink Race Condition

A symlink (symbolic link) race condition occurs when a privileged program performs operations on a file whose path can be manipulated by an attacker during a brief window between two operations. For example, a program might check the permissions of a file (e.g., owned by root) and then, assuming it's safe, perform an operation like `chmod` on it. If an attacker can replace the original file with a symlink to a different target (e.g., `/etc/passwd`) *between* the permission check and the `chmod` operation, the `chmod` will be applied to the attacker's target, potentially leading to privilege escalation by modifying sensitive system files.

Our plan is to:

  1. Remove the existing /var/log/below/error_root.log file.
  2. Create a symbolic link named error_root.log that points to /etc/passwd.
  3. Execute sudo below. When below attempts to set permissions on error_root.log, it will actually modify /etc/passwd, changing its permissions to 666.
  4. Once /etc/passwd is writable by everyone, we can add a new root user and switch to it.
Why

The below binary, when run with elevated privileges (via sudo), creates and then changes the permissions of specific log files. By leveraging a symlink race, we can trick below into applying these permissive 666 permissions to a critical system file like /etc/passwd. This allows us to modify /etc/passwd, a normally restricted file, and achieve root access.

Why

By making /etc/passwd world-writable, we can append a new user entry that has a User ID (UID) and Group ID (GID) of 0. In Unix-like systems, UID 0 corresponds to the root user, granting full administrative privileges. This effectively creates a new root user that we can then switch to.

Summary & Timeline

Lessons Learned
  • Assumed Breach: Starting with credentials often means immediate focus on web applications and common vulnerabilities.
  • RoundCube RCE (CVE-2023-5631): Post-authentication deserialization vulnerabilities can lead to RCE. It's crucial to identify the exact version and use compatible exploit code, ideally in the application's native language (PHP for PHP apps).
  • PHP Session Analysis: Sensitive data, like encrypted passwords, can be stored in PHP sessions, especially in webmail applications that interact with backend mail services. Knowing where to look (database `session` table) and having decryption keys (from `config.inc.php`) is key.
  • Triple DES (3DES) Decryption: Understanding encryption algorithms and how to find IVs (e.g., first 8 bytes of ciphertext) for manual decryption.
  • `sudo -l` Enumeration: Always check sudo -l for privileged binaries. Even if an explicit exploit isn't immediately obvious, the allowed commands can hint at interesting attack vectors or misconfigurations.
  • Below CVE-2023-49089 (Symlink Race): Vulnerabilities in privileged programs that manipulate file permissions (like chmod) can be exploited using symlink race conditions to target sensitive system files (e.g., /etc/passwd).
  • `passwd` File Manipulation: Once /etc/passwd is writable, adding a new user with UID 0 is a direct path to root access.
  • Docker Environment Awareness: Recognizing containerized environments (e.g., Python missing) helps in adapting tools and techniques for shell upgrades.
